扩展屏幕管理 · 交互规格

三个 SwiftUI 窗口：扩展屏幕管理（信息列表）、屏幕修改窗口（逐屏修改与添加）、配对窗口（PIN 输入）。列表只读为主、修改入独立窗口、配对在 App 内完成；无确认弹窗，后果写在控件文案，忙碌置灰。

图例 圆角矩形 = 步骤 / 窗口 菱形 = 判定 圆柱 = 文件写入 macOS 窗口框 = UI 设计示意（按当前主题渲染） ● 串流中 ○ 空闲 / 未启用 ▲ 离线
S1

窗口关系总览

菜单栏（保持现状：状态显示 + 「扩展屏幕管理…」入口）打开 W1；W1 的每屏按钮分别打开 W2（修改 / 添加自定义）与 W3（配对）；添加菜单选预设即建屏。所有修改即时生效，无统一「应用」暂存。

W1 扩展屏幕管理（信息列表）

窗口标题与菜单项同名。每屏一行卡片：只读信息（状态 / IP:端口 / 同步状态）+ 内联控件（启用开关、重启该屏、Web UI、配对…、修改…）。底部工具栏：添加屏幕… 与 保持显示器缩放。状态 1 秒自动刷新（日志尾随）。

W2 屏幕修改窗口

逐屏独立浮层（380×360）。修改模式标题「修改屏幕 — 屏名」；添加模式标题「添加屏幕」（唯一添加入口）。预设下拉按分组（MacBook 5 / iPad 6 / Apple 显示器 3 / 通用 4）选中即填充宽/高/刷新率与 HiDPI 开关（每个预设自带 HiDPI 支持标记），再手改字段则回到自定义。删除不在本窗口——在 W1 列表卡片。SwiftUI 默认控件风格。

W3 配对窗口（PIN）

逐屏独立浮层（360×280）。打开即确保实例 Web 凭据可用（空则自动预置），随后 2s 轮询待配对设备；用户输入 Moonlight 显示的 4 位 PIN 提交。首屏打开时为 Web UI 引导形态（主实例凭据归用户，不接管）。布局：待配对设备行 → PIN 输入（4 格）→ 提交配对 / 关闭 → 结果区。

枚举清单

枚举值语义
ScreenStatestreaming串流中（客户端已连接该屏）
idle空闲（屏在、实例在、无串流）
disabled未启用（配置保留、屏与实例不在）
offline离线（已启用但屏或实例异常）
PairingResultsuccess配对成功，客户端已持久化，可连接
rejectedPIN 错误或签名验证失败；客户端重试新 PIN 后可再提交
expired配对会话超期；回到轮询等待客户端重新发起
EditWindowModeedit修改模式：含删除按钮，应用 = 更新槽位并重建该屏
add添加模式：无删除按钮，应用 = 新建槽位并建屏起实例

规则级别处置

身份向量撞车（同名同尺寸）错误W2 就地报错，提示改名称或尺寸
删除首屏错误删除按钮禁用（文案注明首屏不可删除）
删除屏警告按钮文案自带后果，点击即删（停实例 + 销屏 + 清实例目录），其余屏不受影响
改名警告名称旁常驻警示；应用即重建该屏（位置与 Retina 记忆重置一次）
启用时冻结端口被占错误就地报错，端口不迁移
停用屏的重启 / Web UI / 配对置灰按钮禁用（实例不在运行）；修改… 仍可用
实例凭据已被用户自设提示W3 降级：提示 + 打开 Web UI 按钮（尊重用户凭据）
首屏配对提示W3 显示 Web UI 配对引导（主实例凭据归用户，不接管）
PIN 提交失败 / 会话超时警告结果区就地显示；失败可重输，超时回轮询
轮询网络错误提示就地显示，继续轮询，无弹窗
