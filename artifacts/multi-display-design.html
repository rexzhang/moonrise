MOONRISE · 设计文档

多扩展屏幕设计

1-N 块虚拟扩展屏：每屏独立分辨率与 HiDPI、独立可连的串流实例（Moon N 自动命名，主机名与屏名对应）、逐屏启用开关（持久化）、菜单栏状态可见；全部管理操作收敛于统一管理窗口，菜单栏只做状态显示。

图例 圆角矩形 = 操作步骤 菱形 = 判定 圆柱 = 配置/状态文件写入 圆 = 起止 错误警告自动提示 = 规则级别 ● 串流中 ○ 空闲/未启用 ▲ 离线
S1

总体架构与数据流

每块屏绑定一个 Sunshine 实例。首屏绑定用户主 sunshine.conf（默认端口 47989，不可删除）；第 2..N 屏绑定 MoonRise 自有实例（实例目录含独立 conf、独立二进制副本、独立凭据与日志，端口 48089 起步进 100），由 MoonRise 子进程托管、不受 brew 编排影响；二进制副本独立路径是 macOS 27 同路径捕获串行化的对策（spike S7）。变更经 diff 收敛且只对已启用屏生效：只动目标屏，保留屏的串流不中断。实例主机名 sunshine_name = 屏幕显示名，所有屏一致。

S2

生命周期状态机

屏幕槽位的「已停用」态：配置槽位与冻结属性保留，屏幕与实例不在运行；开关状态持久化，重启后按上次状态恢复。删除为标记式：卡片标记待删除，统一应用时才真正移除槽位并清理实例目录。实例进程独立成机，异常退出走退避重启。

stateDiagram-v2
    direction TB
    state "已停用（配置槽位保留）" as Disabled
    state "待删除（标记，可撤销）" as PendingDelete
    state "创建中" as Creating
    state "运行中" as Running
    state "重建中" as Rebuilding
    [*] --> Creating: 新增屏幕（预设即建，冻结命名与端口）
    Creating --> Running: 激活且边界合法
    Creating --> [*]: 带盐重试仍失败（回滚移除槽位）
    Running --> Rebuilding: 改分辨率 / 改名 / HiDPI 切换（应用）
    Rebuilding --> Running: 新屏就绪并重同步实例
    Running --> Disabled: 停用（应用：停实例 + 销屏，槽位保留）
    Disabled --> Creating: 启用（按冻结端口重建）
    Running --> PendingDelete: 卡片点击删除（标记置灰，可撤销）
    PendingDelete --> Running: 再次点击撤销标记
    PendingDelete --> [*]: 统一应用（移除槽位 + 清理实例目录；首屏除外）

屏幕槽位状态机（rebuild 只影响单槽；停用与待删除屏不被看门狗/回调复活）

stateDiagram-v2
    direction TB
    state "未启动" as Stopped
    state "运行中" as Up
    state "退避重启中" as Backoff
    [*] --> Stopped
    Stopped --> Up: 同步成功 / 保活拉起
    Up --> Up: 值未变（幂等保活）
    Up --> Backoff: 异常退出（5s 起倍增，封顶 60s）
    Backoff --> Up: 延迟到期重新拉起
    Up --> Stopped: 停用 / 删除 / App 退出

Sunshine 实例进程状态机（每屏一个实例，互不影响；首屏按 restartPolicy 编排）

S5

客户端发现与配对

自动发现是硬需求：服务端 mDNS 按实例注册、端口随实例派生，同机多实例由系统自动加后缀区分；连接后主机名 = sunshine_name，与屏名一一对应，方便用户选择。客户端实测覆盖一台 Mac（moonlight-qt）+ 一台 iPad；手动添加 IP：端口 为兜底主路径。配对优先共享 CA（一次配对全实例可用）。多客户端并发输入不限制（共享物理光标，文档标注）。

S7

Spike 验证项（实施前置）

2026-11-10 已完成（M4 · macOS 27.2 · Sunshine 2026.914.233613），完整记录见 Plans/multi-display-spike.md。客户端：一台 Mac（moonlight-qt）+ 一台 iPad。

#验证项结果结论 / 对策
S1双实例共存通过两实例存活、各自钉住各自屏；前提为不同二进制路径（见 S7）
S2共享 CA 免重复配对不成立客户端按主机条目各自配对；逐实例 PIN + 管理窗口配对引导转正（用户已接受）
S3双并发串流通过双路 VideoToolbox ≥12 分钟零断连，单路约 38% CPU
S4输入注入坐标通过键鼠各归各屏，四角点击无串扰
S5日志分流 + 串流标记通过log_path 逐实例分流有效；实例状态文件独立；无共享写冲突
S6自动发现 + 名称对应部分通过自动发现不可用（客户端按 IP 去重），手动添加为主路径；sunshine_name 名称对应实测有效
S7捕获路径序列化（新发现）关键机制同二进制路径并发捕获即永久挂起；对策 = 每实例独立二进制副本路径；遗留验证：MoonRise 归属下双子进程并发捕获（实现期 R3 验收必做）
S8

关键对象

设计层对象卡：类型为概念标注（实现语言类型见实施）。

AppConfig

应用配置（config.json）

  • displays屏幕槽位数组
  • keepHostScaling布尔（全局）
  • sunshine全局 Sunshine 设置

DisplayConfig

单屏槽位（displays 元素）

  • idUUID（持久锚）
  • slotNumber整数（留洞编号）
  • name文本（自动 Moon N，可改唯一名）
  • width / height / refreshRate整数
  • hiDPI布尔（默认开）
  • enabled布尔（开关状态，持久化）
  • sunshinePort整数或空（首屏空 = 主配置）

实例 conf 键集

第 2..N 屏实例配置（允许代建）

  • output_name该屏 displayID
  • sunshine_name屏幕显示名（客户端主机名）
  • stream_audioenabled / disabled（全局同值）
  • port实例 base 端口（冻结）
  • credentials_file指向实例目录（独立配对状态）
  • pkey / cert实例目录内独立 CA（spike S2：凭据自包含）
  • log_path按实例分流（spike S5 实测有效）

ScreenRuntimeState

诊断状态（state.json，只写不读）

  • slotID / name槽位与显示名
  • displayID系统显示器标识
  • spec宽高 / 刷新率 / HiDPI
  • enabled开关状态
  • streaming串流中 / 空闲
  • port实例端口
  • syncStatus实例同步结果

规则级别处置
显示名重复错误应用时就地报错，提示冲突

改名警告名称旁静态警示文案，应用直接执行；重置该屏位置与 Retina 记忆
删除屏（含串流中）警告标记式待应用（卡片置灰、可撤销），应用文案标注含删除 N 屏；按钮文案自带后果提示

启用时冻结端口被占错误端口不迁移，报错并提示诊断
停用首屏自动允许；主实例一并停止，防 output_name 悬空回退捕获 host 屏
实例 conf 缺失自动代建（MoonRise 自有文件）
实例二进制副本与源不一致自动刷新副本并重启该实例（brew 升级后跟随）
同一路径并发捕获（macOS 27）自动每实例独立二进制副本路径（spike S7）；实例启动/重启串行化
