S0 概览

Sunshine 二进制来源唯一化为受管目录（官方 release 整 bundle），获取仅由用户在设置窗口手动触发；设置全部收敛到 UserDefaults 单源（ConfigStore）；brew 支持整体移除；Sunshine 未就绪时全 App 进入锁定态并用上游原生 system_tray 键抑制托盘。总体状态只有两态，瞬态阶段（下载/验签/换装）是 Sunshine 页内的任务进度，不是就绪状态：

stateDiagram-v2
    [*] --> locked : 启动 · 受管目录缺失或验签不过
    [*] --> ready : 启动 · 受管目录就绪
    locked --> ready : 用户手动获取成功（下载→验签→换装）
    ready --> ready : 更新换装成功（旧版被替换）
    ready --> ready : 更新失败（旧版保留，报错呈现）
    note right of locked
        全程不建屏 / 不启实例 / 不同步 conf
        菜单栏锁定行 · 屏幕管理页遮罩
    end note
    note right of ready
        建屏 · 实例 · conf 同步 · 托盘(system_tray=disabled)
    end note

S1 数据结构

ConfigStore（新组件）

ConfigStore（@Observable，MoonRiseCore/Config/ConfigStore.swift）

成员类型语义
currentAppConfig只读快照；编排层 configProvider 与菜单/页面读取入口
mutate(_:)(inout AppConfig) -> Void唯一写通道：改 → UserDefaults 持久化 → Observation 通知
readiness（关联派生）由 ManagedSunshineStore 提供锁定/就绪判定（见 S2 状态机）

持久化 = UserDefaults 标准 suite 单键 appConfig（JSON blob，原子写语义不变）；AppConfig 值类型与解析容错逻辑原样保留。设置窗口/菜单不再触碰 AppController 私有 config。

AppConfig schema（演变后）

AppConfig（Codable struct，字段级）

字段类型默认约束 / 来源
displays[DisplayConfig]Moon 1 单槽不变；槽位 UUID/名称/规格/端口/启用
keepHostScalingBooltrue不变
sunshine.configPathString~/.config/sunshine/sunshine.conf不变；Sunshine 自身约定路径
sunshine.autoConfigureBooltrue不变；SunshineSync 功能开关
sunshine.disableAudioStreamingBooltrue不变
sunshine.selectedVersionString"latest"新增；"latest" 或具体 tag（"v2026.1112.40957"）；检查更新与重新获取的比较基准
sunshine.restartPolicy / hideTrayIcon / binaryPath——字段删除；旧 JSON 残留键被解码器忽略

Package.swift 平台目标上调 .macOS(.v14)（@Observable 依赖）。

UserDefaults 键清单

键类型语义
appConfigData（JSON blob）全部设置（上表 schema）
sunshine.migrationDoneBool操作标志：legacy 迁移提示已处理（独立于设置 blob）

不进 store：state.json（运行态事实）、SMAppService（系统自管）、Sunshine 实例凭据文件。首启迁移：检测旧 ~/.config/moonrise/config.json → 导入 blob → 原文件改名归档 config.json.imported。

conf 目标键集（ConfFile 行级编辑，值变才重启精确到实例）

键集键（类型均为 String）system_tray 值语义
主 conf（4 键）output_name / stream_audio / sunshine_name / system_tray恒写 disabled；上游 to_bool 仅认 true/yes/enabled/on/含"1"，其余为假（v2026.1112.40957 src/config.cpp:1891）→ 托盘不创建且跳过主线程事件循环（src/main.cpp:156-162）。主 conf 缺失时 MoonRise 代建（键取默认值）。
实例 conf（10 键）主 conf 四键 + port / log_path / pkey / cert / credentials_file / file_state

S2 交互流程

状态机：SunshineReadiness

就绪判定只有两态，且唯一来源是受管副本：brew 遗留、手动安装于任意位置的官方 app、损坏/缺失的受管目录一律视为未获取（等同首次获取，走锁定态与引导流程）；下载/验签/换装全部是任务瞬态，呈现于 Sunshine 页进度区，不改变 readiness：

stateDiagram-v2
    direction LR
    state 判定条件 {
        locked : locked（未就绪）
        ready : ready（就绪）
    }
    [*] --> 判定条件 : 启动解析受管目录
    判定条件 : 受管副本存在（获取流程落位）
    判定条件 : 落位时验签通过
    判定条件 : 且内层二进制可执行

时序 1：首次获取（锁定态引导 → 就绪）

sequenceDiagram
    participant U as 用户
    participant P as 设置窗口·Sunshine页
    participant M as ManagedSunshineStore
    participant G as GitHub API
    participant A as AppController/编排
    A->>P: 启动解析失败 → 自动打开 Sunshine 页（锁定）
    U->>P: 选版本（跟随最新 / 具体 tag）→ 点「获取」
    P->>M: download(selectedVersion)
    M->>G: GET releases/latest（或按 tag 查列表）
    G-->>M: assets[] → Sunshine-macOS-arm64.dmg
    M->>G: 下载 DMG（进度回调 → 页面进度区）
    M->>M: hdiutil 挂载 → cp -R → codesign 验签（TeamID + 版本核对）
    alt 验签失败 / 下载失败
        M->>M: detach + 清理 staging
        M-->>P: 失败态文案（手动重试）
    else 通过
        M->>A: 停全部实例（串行，锁定态本就无实例）
        M->>M: 原子换装 → 受管目录就位
        M->>A: readiness 翻转 → 建屏 / 起实例 / 副本 SHA 刷新
        M-->>P: 就绪（版本徽标 + 来源路径更新）
    end

时序 2：更新换装（ready 态，实例在跑）

sequenceDiagram
    participant U as 用户
    participant P as 设置窗口·Sunshine页
    participant M as ManagedSunshineStore
    participant A as AppController/编排
    participant I as Sunshine 实例（主+扩展）
    U->>P: 检查更新 → 有新版 → 点「更新」
    P->>M: download(新版 tag)
    M-->>P: 下载+验签完成（staging 就绪）
    M->>A: 停全部实例（串行；主 conf 值未变不触发误重启）
    A->>I: SIGTERM → 等待退出（串行逐个）
    M->>M: 原子换装（旧目录改名遗留后删除）
    M->>A: registry forget 全部 → 按配置重建
    A->>I: 重启实例 → ensureBinaryCopy 检测 SHA 不一致 → 整 bundle 副本刷新
    A-->>U: 串流恢复（客户端自动重连）

时序 3：迁移收编（存量机器）

sequenceDiagram
    participant U as 用户
    participant P as 设置窗口·Sunshine页
    participant M as ManagedSunshineStore
    participant C as ~/.config/sunshine/
    A->>P: 启动检测 legacy 信号（binaryPath 键 / conf+credentials 存在）
    P-->>U: 迁移提示条「检测到既有 Sunshine 配置与凭据，将原样沿用」
    U->>P: 点「获取」（受管副本）
    P->>M: download(selectedVersion)
    M-->>P: 换装完成（同时序 1）
    P->>C: 无任何文件操作（conf/凭据/配对原地沿用）
    note over P,C: 迁移不视为已获取——获取成功前维持锁定态，既有二进制不参与就绪判定
    A->>A: 主 conf 同步（键集含 system_tray）→ 首屏凭据预置（provisionCredentialsIfNeeded）

时序 4：检查更新（手动，无自动触发）

sequenceDiagram
    participant U as 用户
    participant P as 设置窗口·Sunshine页
    participant M as ManagedSunshineStore
    participant G as GitHub API
    U->>P: 点「检查更新」
    P->>M: checkLatest()
    M->>G: GET releases/latest
    G-->>M: tag_name + assets
    M->>M: 与 selectedVersion 语义比较（latest=比已装版本；钉住=比所选 tag）
    alt 已装 < 最新
        M-->>P: 「有新版本 vX（含 ≥v2026.1112 警示规则）」+ 更新按钮高亮
    else 已是最新
        M-->>P: 「已是最新」
    end

S3 接口契约

GitHub Releases API

项契约
端点GET https://api.github.com/repos/SunshineStream/Sunshine/releases/latest；GET …/releases?per_page=20（版本列表，过滤 draft 不取、prerelease 仅列出不默认选中）
认证 / 限流免认证；60 次/时/IP；仅手动触发，无轮询。HTTP 403（rate limit）→ 呈现限流提示（读 X-RateLimit-Reset 显示剩余分钟）+ 手动重试
资产匹配（芯片类型）name == "Sunshine-macOS-\(arch).dmg"；arch ∈ {arm64, x86_64}（ProcessInfo().machine 映射）；取 browser_download_url 与 size（进度分母）。release 缺本机架构资产 → 该版本不可获取，版本列表标注且不可发起下载
最低支持版本常量 v2026.1112（S8：此前的 AVFoundation 捕获路径在 macOS 27 有串屏/停滞缺陷）；UI 固定说明 + 列表低于该值标注「不支持」+ 选择/安装时警示条（不阻断）
tag 解析vYYYY.MMDD.序号 数字分段比较（版本新旧判定与 ≥v2026.1112 警示共用）
下载URLSession downloadTask（自动跟随 objects.githubusercontent.com 跳转）；失败不自动重试，呈现错误态 + 手动重试

验签契约（拒绝落位的硬校验）

步骤命令 / 读取通过判据
身份codesign -dv <bundle>TeamIdentifier=F8XQ7XCN2R（LizardByte Developer ID）
版本Info.plist CFBundleShortVersionString与所请求 tag 版本段一致（v2026.1112.40957 → 2026.1112.40957）
可执行内层二进制 POSIX 0755 + FileManager.isExecutableFile真

任一不符：拒绝落位、detach、清 staging、页面错误态。验签使任何下载镜像路径安全（不过验签即不可信）。

hdiutil 提取链

步骤命令失败处置
挂载hdiutil attach -nobrowse -readonly -mountpoint <staging/mnt> <dmg>清 staging，错误态呈现
提取cp -R <mnt>/Sunshine.app <staging>/同上
卸载hdiutil detach <staging/mnt> -quiet急切清理分支必经（成功/失败都执行）

换装契约（与现有机制的衔接）

  • 原子换装：旧 Sunshine.app 改名遗留 → 新目录 mv 就位 → 删遗留（同盘 rename 原子性）。
  • 换装前停全部实例（串行，逐个 SIGTERM → 等待退出）；主 conf 值未变不触发 conf 变更重启。
  • 换装后 registry forget 全部 → 按配置重建：实例副本由 InstanceConf.ensureBinaryCopy 按 SHA-256 对锚自动整 bundle 刷新（S8 既有机制）。
  • 启动解析（非更新路径）：受管目录存在 + 内层二进制可执行 → ready；否则 locked（不验签重跑，信任落位时验签）。

S5 错误与冲突规则（概览）

情形级别处置
下载失败（网络 / 404 资产缺失）任务错误错误态文案 + 手动重试；staging 清理
GitHub 限流 403任务错误限流提示（重置剩余分钟）+ 手动重试
验签不符 / 版本不符硬失败拒绝落位 + 清 staging；错误态点名原因
所选版本 < v2026.1112警示警示条（S8 缺陷说明），允许继续
换装时实例停止失败硬失败中止换装（旧版保留就绪），错误呈现
受管目录运行中被手动破坏运行错误实例异常退出 → 退避重启失败 → 看门狗对账转锁定态
release 缺本机架构资产不可获取版本列表标注，不可发起下载（芯片类型规则）
迁移提示重复出现体验sunshine.migrationDone 标记一次性；提示条只随 legacy 信号出现
